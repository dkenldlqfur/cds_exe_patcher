# CDS_95.EXE 분석 기록

한국어판 `CDS_95.EXE`에서 확인한 패처 관련 코드와 데이터 연결을 기록한다. 주소는 별도 표기가 없으면 가상 주소(VA)다.

## 월드 지도 도시 이름 표시

도시 발견 루틴은 `0x48D916`에서 발견한 도시 ID를 EBP에 보관한다. 대사 인물 ID가 있으면 `제독, 도시가 보입니다!`를 `0x478280`으로 표시하고, 없으면 `도시를 발견했습니다!`를 `0x49E3E0`으로 표시한다. 대사 경로의 `0x48DA06` 점프는 일반 알림을 건너뛰므로 두 기존 문구는 한 발견에서 둘 중 하나만 나온다.

기타 수정의 **월드 지도 도시 이름 표시**는 지도 위 이름만 표시한다. 기존 도시 발견 대사·알림은 그대로 유지하고 추가 공용 팝업은 표시하지 않는다. `0x48D9FE`의 `0x478280` CALL과 `0x48DA11`의 `0x49E3E0` CALL은 원본 상태로 둔다. 이전 팝업 패치는 정확한 식별자·명령을 검증한 뒤 이 두 CALL과 팝업 코드를 원상복원한다.

### 월드 지도 도시 이름

지도 출력 루틴 `0x48A1E0`의 타일·선박·애니메이션 출력 이후인 `0x48AB38`을 별도 래퍼로 연결한다. 원래의 `mov ecx,[esp+14h]; test byte ptr [ecx+A0h],1` 11바이트를 래퍼 끝에서 다시 실행하고 `0x48AB43`으로 복귀한다. 지도 대신 비공개 배경을 출력하는 경로는 이 훅을 통과하지 않는다.

- 도시 226개를 순회하며 런타임 도시 레코드 `+0x04`의 `flags & 1 != 0`, `flags & 4 == 0`인 도시만 사용한다. 원본 지도에서 도시 타일을 표시하는 것과 같은 조건이다.
- 도시 마스터의 X/Y(`+0x04/+0x08`)와 그림 영역 크기(`+0x0C`)로 화면 안에 도시 그림이 있는지 검사한다.
- 화면 시작 타일은 `0x5B63A8/0x5B63AC`다. 상대 X는 2500칸 세계지도 좌우 연결을 반영한다. 화면 너비/높이는 지도 객체의 `+0xEC/+0xF0`에서 매번 읽는다.
- 도시 이름은 그림의 한 타일 위, `[현재 국가 이름]`은 그 위 한 행에 표시한다. 두 행의 간격은 v6의 18픽셀에서 v7의 `16 + 테두리 굵기 × 2`픽셀로 일반화했다. 가운데 X는 `상대 도시 X × 16 + 그림 영역 크기 × 8`이다. 각 행의 왼쪽 X는 `가운데 X - CP949 바이트 수 × 4`로 개별 계산한다. 이전 v2/v3의 여백 포함 타일 폭으로 정렬하면 이름이 왼쪽으로 치우칠 수 있어 v4에서는 픽셀 단위로 변경했다.
- 국가 ID는 도시 런타임 레코드 `+0x00`에서 매번 읽는다. 마스터의 초기 국가 `+0x24`와 달리 역사 이벤트에 의한 점령·소속 변경을 반영한다. 국가 이름은 `0x4CA370 + ID × 0x18`의 첫 문자열 포인터이며 국가 0~77을 지원한다. ID·포인터·문자열이 없으면 도시 이름만 표시한다. 대괄호를 포함하는 임시 문자열 버퍼는 128바이트이고, 너무 긴 국가 이름은 CP949 중간 절단 없이 생략한다.
- 픽셀 텍스트 보조 함수는 기존 `0x426860`처럼 지도 객체의 화면 원점(`+0x28/+0x54`)을 합쳐 적용하고 이전 원점을 복원한다. v4/v5는 `0x406800(x,y,name,color)`를 호출하고, v6는 같은 인수의 지도 이름 전용 테두리 출력 함수를 호출한다. 가로 양끝에 테두리 여백을 두고, 화면보다 넓은 행은 생략한다. 위쪽 가장자리에서도 두 행을 화면 안에 배치한다.
- 두 이름 행과 인접 행의 타일 캐시를 `0xFFFF`로 무효화한다. 다음 프레임에서 바탕 타일을 다시 그려 스크롤·외곽선 잔상을 지운다. 캐시 범위는 화면 높이 안으로 제한한다.

지도 코드는 기존 병종 슬롯 뒤의 `.patch +0x51200`에 저장한다. v8 슬롯 크기도 `0x600`바이트로, 뒤에 있는 고속 항해 수정 슬롯의 위치를 변경하지 않는다. 이전 v1(팝업), v2(팝업·지도), v3(지도만), v4(국가명·픽셀 가운데 정렬), v5(관계별 색상), v6(검은색 1픽셀 테두리), v7(테두리 설정)도 정확한 바이트를 검증해 읽고 체크 상태를 유지하며 저장 시 v8로 갱신한다. 글자 색상 6개와 테두리 색상은 보존하며 현재 패처의 저장 굵기는 테두리 표시를 켜면 1, 끄면 0이다. 이전 팝업 문자열은 제거하고 예약 공간 일부를 픽셀 텍스트 보조 함수로 재사용한다. 체크 해제 시 지도 훅을 원본으로 복원하고 해당 슬롯을 비우며, 이전 버전에서는 팝업 CALL도 복원한다. `WORLD.CDS`나 세이브 데이터는 수정하지 않는다.

### 국가 관계별 글자 색상 (페이로드 v5)

내용 팝업에서 국가명과 도시명의 자국·우호국·적국 색상을 각각 선택한다. 기본값은 기존 표시와 같은 흰색(10)이다. 여기의 관계는 **지도 표시용 분류**이며 별도의 외교 상태를 새로 만들거나 게임의 출입 판정을 변경하지 않는다.

1. 도시의 현재 국가 ID가 유효한 0~77이고 현재 소속 국가 `0x5B394C`와 같으면 자국이다. 이 전역값은 후원 계약 시 후원자 국가로, 계약 종료 시 주인공 국가로 갱신된다.
2. 나머지는 국가 런타임 레코드 `0x5859C0 + 국가 ID × 0x10`의 `+0x0C`가 0보다 크거나 기존 조약 함수 `0x469880(국가 ID)`가 참이면 적국 색상으로 표시한다. 전자는 도시 접근 경로 `0x4687F4`에서 `0x429D90`을 통해 검사하는 진입 제한값이다. 후자는 도시 진입의 `0x46AB90`에서 사용하는 검사이며, 현재 연도 `0x5A4D20`이 1494년 이상이고 소속국/도시 국가가 포르투갈(0)·에스파냐(1)의 반대편일 때 참이다.
3. 그 외에는 우호국 색상을 쓴다. 따라서 여기서 우호국은 명시적인 동맹 플래그가 아니라 자국·적국 조건에 해당하지 않는 국가를 뜻한다. 잘못된 국가 ID는 배열에 접근하지 않고 도시명만 우호국 색상으로 표시한다.

종교 3/4 검사(`0x4A56D0`)는 적대 도시 메뉴에서 잠입 항목을 결정하는 데 쓰이므로 일반적인 적국 판정으로 사용하지 않는다. 국가 레코드 `+0x08`의 조약 위반 기록도 색상 판정에 넣지 않는다. 국가의 현재 소속·출입 상태·조약 조건은 지도를 그릴 때마다 읽는다.

글자 출력 `0x406800`의 색상 인수는 RGB가 아닌 팔레트 인덱스다. EXE `0x4FFDD8`의 192바이트 공용 팔레트는 B-R-G 순서이고 64색이 슬롯 10~73에 배치된다. 팝업도 이 데이터를 RGB로 변환해 보여주며, 이미지별로 바뀔 수 있는 다른 팔레트 슬롯은 선택지에서 제외한다. 전역 팔레트는 수정하지 않고 각 글자 호출의 전경색만 전달한다. 기존 외곽선 색상 73은 유지한다.

슬롯 `+0x10`에 국가명 자국/우호국/적국, 도시명 자국/우호국/적국 순서의 6바이트를 저장한다. 픽셀 글자 보조 함수는 색상 인수를 추가한 `thiscall(view,x,y,text,color), ret 16`이며, 관계 함수는 슬롯 `+0x480`에 둔다. 구형 v4의 3인수 글자 함수는 기존 패치 판독에만 유지한다. 저장한 색상을 재로딩하며 좌표 표시 스타일을 바꿔 슬롯을 재생성할 때도 보존한다.

검증은 기계어 에뮬레이션으로 기존 발견 알림만 한 번 나오는지, 실제 외곽선 글자 함수와 픽셀 보조 함수의 화면 원점·캐시 처리, 도시 발견 플래그 필터, 국가 0·77 및 국가명 변경, 한글·영문 혼합 글자 폭, 스크롤·좌우 연결·가장자리 배치와 레지스터/스택 보존을 확인한다. 이전 v1/v2/v3/v4의 이행과 해제·재저장, 6개 색상, 소속국·진입 제한·1494년 조약, 팔레트 B-R-G 변환 및 좌표 스타일 변경 후 색상 보존도 검사한다. 최종 하드웨어 글자 출력은 테스트에서 대체하므로 실제 게임 화면의 외관·성능은 별도 플레이 검증이 필요하다.

### 사방 1픽셀 테두리 (페이로드 v6)

기존 `0x406800`은 `0x52F658`의 X 오프셋 `-1, 2, 0, 1`로 네 번 출력한다. 처음 두 번만 검은색(73), 나머지 두 번은 지정 색상이고 Y는 바뀌지 않는다. 따라서 상하 테두리는 없고 전경 글자는 가로 1픽셀을 겹쳐 그린 굵은 글자다.

v6는 이 굵기를 그대로 유지하면서 1픽셀 사방 테두리를 추가한다. 지도 슬롯 `+0x500`의 전용 cdecl 함수가 먼저 검은색으로 `(-1,0), (2,0), (0,-1), (1,-1), (0,1), (1,1)`에 출력한 뒤, 지정 색상으로 `(0,0), (1,0)`에 출력한다. 각 좌표는 원래 글자 원점에 대한 상대값이다. `+0x400`에 이 8쌍의 좌표를 보관하며 원본 `0x406800`과 공용 오프셋 배열은 변경하지 않으므로 다른 메뉴에는 적용되지 않는다. 색상 지정(`0x4B5DEA`), 글자 출력(`0x4B6071`), 글자 커서 전역값 갱신은 원본과 같은 경로를 사용한다.

CP949 바이트 폭을 W라 하면 굵은 전경 폭은 W+1이고 테두리까지 W+3이다. 오른쪽 경계는 `화면 폭 - W - 2`로 제한한다. 16픽셀 높이 글자 두 줄이 테두리끼리 겹치지 않도록 국가명을 도시명보다 18픽셀 위에 두며, 도시명 최소 Y를 19로 잡아 국가명 위 테두리도 화면 안에 둔다. 기존 인접 타일 행 무효화 범위가 새 테두리까지 포함하므로 별도의 캐시 범위 확장은 하지 않는다.

기계어 테스트는 검은색 6회/전경색 2회의 실제 그리기 좌표·색상, 두 행의 간격, 화면 네 변의 테두리 범위와 캐시, v5 색상 보존 이행, 공용 글자 함수·배열 불변을 검사한다. 버전 번호 v6는 패치 페이로드의 내부 형식이며 앱 배포 버전과는 별개다.

### 테두리 굵기·색상 설정 (페이로드 v7)

v7에서는 내용 팝업에서 국가명·도시명 공통 테두리를 0~3픽셀로 설정했다. 0은 테두리 없음이며 전경 글자의 원래 굵기는 유지한다. 테두리 색상은 EXE 공용 팔레트 10~73 중에서 선택한다. 초기값은 v6와 같은 `(1,73)`이고, 확인 전 변경은 미리보기에만 반영하며 취소하면 버린다. 아래 v8부터 굵기 조절 UI는 제거하고, 테두리 표시 여부만 선택하며 켰을 때는 1픽셀로 고정한다.

슬롯 헤더 `+0x16/+0x17`에 굵기·팔레트 번호를 각 1바이트 저장한다. `+0x400`의 좌표표는 v6의 i32 두 개 대신 **부호 있는 i8 두 개**로 압축하고 전용 렌더러에서 부호 확장한다. 굵기 r의 테두리는 원래 전경 오프셋 `(0,0),(1,0)`을 각각 `|dx|+|dy| <= r` 범위로 확장한 합집합이다. 안쪽 좌표도 포함해 가는 획 주변에 빈틈이 생기지 않게 하고, 전경 두 번은 항상 마지막에 출력한다. r=0/1/2/3일 때 총 출력 횟수는 2/8/18/32회이며, 1픽셀 좌표 순서는 v6와 같다. 최대 좌표표 크기도 64바이트여서 기존 예약 공간에 들어간다.

글자 폭 W와 테두리 r에 대해 가로 점유 폭은 `W+1+2r`, 왼쪽 제한은 r, 오른쪽 제한은 `화면 폭-W-1-r`이다. 두 행 간격은 `16+2r`, 도시명 최소 Y는 `16+3r`, 최대 Y는 `화면 높이-16-r`이다. 캐시 무효화는 위쪽 실제 픽셀 `도시명 Y-16-3r`부터 아래쪽 실제 픽셀 `도시명 Y+15+r`까지 포함하는 타일 행으로 계산한다. 굵기 2~3에서는 이전의 고정 행 수로 놓칠 수 있던 아래쪽 행도 지운다.

리로딩·색상만 변경·좌표 표시 스타일 변경 시 테두리 설정을 함께 보존한다. 잘못된 굵기·팔레트 값이나 코드/좌표표 변조는 적용 전 검사에서 거부한다. v6까지의 페이로드 생성은 바이트 단위로 유지해 이전 EXE 판독·갱신·해제가 가능하다. 검증은 0~3픽셀의 실제 출력 좌표/색상·경계·캐시, 설정 저장/복원, v6 이행과 고속 항해 슬롯 보존을 포함한다.

### 국가명·테두리 표시 선택, 테두리 1픽셀 고정 (페이로드 v8)

내용 팝업의 **국가 이름 표시** 체크박스로 위쪽 국가명 행을 켜거나 끈다. 기본값 및 구버전 판독값은 켜짐이다. 슬롯 헤더 `+0x18`의 1바이트에 0/1을 저장하며 다른 값은 손상된 설정으로 거부한다. 끄면 도시명 출력 직후 캐시 처리로 분기하여 국가명 포인터 조회·문자열 복사·출력을 모두 건너뛴다. 도시의 소속 국가 판정은 그대로 수행하므로 도시명 자국/우호국/적국 색상은 유지된다. 국가명 색상도 삭제하지 않아 다시 켜면 이전 색상을 쓴다.

국가명을 숨긴 경우 위쪽 여백 및 캐시 시작 범위는 도시명 자신의 테두리만 고려한다. 따라서 지도 위쪽 가장자리에서도 없는 국가명 행을 위한 빈 공간을 남기지 않는다. 국가명 표시 여부는 EXE 재로딩과 좌표 표시 스타일 변경을 거쳐도 보존한다. 팝업에서 취소하면 이전 선택으로 돌아간다.

**테두리 표시** 체크박스로 국가명·도시명의 공통 테두리를 켜거나 끈다. 켜면 **1픽셀 고정**이며 굵기 입력 컨트롤은 제공하지 않는다. 끄면 테두리 색상 선택을 비활성화하지만 선택한 색상은 보존하여 다시 켤 때 사용한다. GUI 로딩과 통합 저장 모두 기존 굵기 0은 꺼짐으로 유지하고, 구형 굵기 1~3은 켜짐(1픽셀)으로 정규화한다. 표시 여부는 기존 헤더 `+0x16`에 0/1로 저장하므로 페이로드 형식은 v8을 유지한다. 국가명 표시 여부와 독립적이며 EXE 재로딩·좌표 스타일 변경 후에도 보존한다. 팝업에서 확인 전 변경은 미리보기에만 적용하고, 취소하면 버리며 기본값은 켜짐·검정이다. 예전 0~3픽셀 데이터를 안전하게 읽고 해제할 수 있도록 저수준 판독·페이로드 생성기의 구형 굵기 지원은 남겨 둔다.

## 인물 능력치와 생명력 상한

| 항목 | 코드 위치 | 원본 상한 | 패처 범위 |
|---|---:|---:|---:|
| 체력·지력·무력·매력·운·신앙심 | `0x432C50` | 100 | 0~255 공통 |
| 생명력 | `0x432C87` | 2000 | 0~9999 |

능력치 함수는 값에 1을 더해 상·하한을 검사한 뒤 다시 1을 뺀다. 255 상한은 부호 확장되는 8비트 즉시값이 아니라 32비트 즉시값으로 기록한다. 생명력 화면 형식은 `HP:%4d`이며, 4자리까지 표시하도록 허용 범위를 9999로 제한한다.

## 자금과 명성 상한

- 소지금과 저금은 서로 다른 내부 판정 경로를 사용하지만, 패처에서는 공통 상한 하나를 제공하고 양쪽에 같은 값을 기록한다.
- 주인공 명성과 악명은 `0x4800E0`의 공통 판정 함수를 사용한다. 패처는 두 값에 같은 상한을 적용한다.
- `0x474188`은 함대 식량 상한 경로이며, 주인공 명성 상한 위치가 아니다.

## 힌트 대상 ID 연결

힌트 마스터의 대상 ID는 발견물 마스터 레코드의 `+0x08` 필드와 대응한다. 대상 ID가 같은 발견물 레코드가 여러 개일 수 있으며, 모두 해당 힌트의 연결 대상으로 표시한다. 상세창은 ID와 발견물 이름을 함께 보여주는 콤보박스를 제공하고, 다른 항목을 선택하면 연결 대상 목록도 다시 구성한다.

## 발견물 그룹 ID

발견물 마스터의 `+0x20`은 16비트 범위(0~65535)의 그룹/대상 ID다. 여러 개별 발견물 레코드가 같은 ID를 공유할 수 있다. 발견물 탭에서는 개별 레코드 번호와 별도로 이 그룹 ID를 편집하며 발견물 목록과 모조품 목록에 표시한다. DISEV의 `01 0B [발견물 ID]` 등록 명령은 개별 발견물 ID를 대상으로 하므로, 그룹 ID를 같게 바꿔도 해당 그룹의 모든 레코드가 자동으로 한꺼번에 등록되는 것은 아니다. 저장 후 힌트와 가짜 아이템의 그룹 대상 이름도 새 ID에 맞춰 다시 구성한다.

발견물 좌표 오버레이의 네 값이 모두 `-1`이면 좌표 없음이다. 좌표 탭의 `좌표 있음/좌표 없음` 선택은 이를 그대로 표시·편집하며, 좌표 없음 저장 시 네 필드를 모두 `-1`로 기록한다.

## 튀니스 주점 아이템 이벤트 위치

도시·시설 이벤트 연결표(VA `0x500918`, 행 크기 `0x38`)에서 `+0x08`은 도시 ID, `+0x0C`는 시설 ID, `+0x1C`는 호출할 DISEV 파트 번호다. 시설 ID는 `Resources/data/city_reference.json`을 기준으로 `1=교역소`, `4=주점`이다.

원본 연결은 카사블랑카(ID 85) 주점의 DISEV 파트 265였고, 튀니스(ID 82) 주점에는 연결이 없었다. 파트 265는 아이템 277번 「지중해의 유혹 1」을 얻는 대화다. 파트 220은 별도의 용연향 교역소 이벤트이므로 이 수정의 대상이 아니다. 버그 수정 옵션은 파트 265 연결만 카사블랑카 주점에서 튀니스 주점으로 옮기며, 체크 해제하면 원래 연결로 복원한다.

도시 탭의 시설 탭에서 **이벤트 연결...**을 열면 선택된 도시의 각 시설에 연결된 DISEV 파트를 직접 편집할 수 있다. 이벤트 파트는 `없음` 또는 0~273으로 지정하며, 저장 시 각 연결 필드만 수정하고 시설 배치 좌표 등 같은 행의 다른 데이터는 보존한다. 튀니스 이벤트 버그 수정 옵션이 켜져 있으면 해당 옵션의 연결이 수동 편집값보다 우선한다.

## 고속 항해 지도 추적 오류

항해 이동량은 `0x48BCF0`에서 계산하고 `0x48D0A0`에서 방향·위도·해류와 잔여 이동량을 반영한 X/Y 이동량으로 변환한다. 이동량에 지도 추적용 상한은 없다. `0x48D356`은 이 이동량을 `0x47D0C0(player, dx, dy)`에 넘긴다.

지도 원점은 주인공 객체의 `+0x308/+0x30C`(`0x5B63A8/AC`, 타일 단위), 주인공 좌표는 `+0x310/+0x314`(`0x5B63B0/B4`, 픽셀 단위)다. 타일은 16픽셀, 세계 너비는 2500타일=40000픽셀이다.

- `0x47D020`은 상대 X가 음수이면 세계 너비를 더해 오른쪽의 큰 양수로 변환한다. 정상적인 작은 이동에서는 왼쪽 4타일의 추적 여유 안에서 먼저 카메라를 이동하므로 문제가 드러나지 않는다. 큰 서쪽 이동이 이 여유를 건너뛰어 화면 원점보다 왼쪽에 도달하면 `0x47D1D8`은 오른쪽 스크롤로 판단한다.
- `0x47D0C0`의 X/Y 카메라 처리는 화면 절반만 이동하고 재검사하지 않는다. 큰 이동에서는 카메라 이동 후에도 주인공이 화면 밖에 남는다.
- 원본 기계어 실행 검증: 640×320 지도, 화면 상대 X=89에서 dx=-88이면 원점이 20타일 왼쪽으로 이동한다. dx=-90이면 20타일 오른쪽으로 이동하고 선박의 화면 X는 39655가 된다. 자원 접근은 테스트에서 대체하며 이동·카메라·좌표 변환은 원본 명령을 실행한다.

개별 버그 수정 **고속 항해 지도 갱신 버그 수정**은 `0x48D356`의 CALL 5바이트만 독립 래퍼로 연결한다. 축별 최대 이동이 32픽셀 이하이면 원래 함수를 한 번 호출한다. 초과하면 `N=ceil(max(abs(dx),abs(dy))/32)`로 나누고, 매번 남은 이동량을 남은 횟수로 부호 있는 나눗셈하여 축별 32픽셀 이하의 이동을 실행한다. 음수·대각선에서도 요청 이동량의 합은 정확히 보존된다. 통과 가능한 지형에서는 총 이동 거리가 같고, 지형 충돌 및 남북 한계는 원래 이동 함수가 처리한다.

날짜 진행·도시 발견·조우 판정은 래퍼 밖의 기존 항해 루프에 그대로 남는다. 작은 좌표 이동마다 원본의 시야 기록·지형 검사가 실행되지만, 추가 날짜나 조우 판정은 없다. `0x47D020`의 다른 사용처나 지도 출력 루틴은 수정하지 않는다. 도시 이름 지도 표시와도 독립적이다.

래퍼는 `.patch +0x51800`의 `0x200`바이트 슬롯을 사용하고 비휘발 레지스터와 `ret 8` 호출 규약을 보존한다. 식별자·훅·주변 원본 명령을 검증하며 해제 시 원래 CALL을 복원하고 슬롯을 비운다. 저장·좌표 표시 스타일 전환 후 상태 판독, 기존 도시 이름 패치와 동시 적용, 서쪽 오류 재현/수정, 큰 이동·음수·대각선·세계 좌우 연결·해상도별 추적·남북 한계·지형 차단을 테스트한다. 최종 게임 화면은 실제 플레이로 추가 확인이 필요하다.

## 월드 지도 선박 중앙 추적

기타 수정의 **월드 지도 선박 중앙 추적**은 기본값 꺼짐인 독립 옵션이다. 원래 `0x47D0C0`은 선박 화면 좌표가 왼쪽·위쪽 4타일, 오른쪽·아래쪽 `화면 타일 수 - 7` 경계에 도달해야 원점을 화면 절반만큼 이동시킨다. 카메라 원점 `0x5B63A8/AC`은 타일 단위인 반면 주인공 위치 `0x5B63B0/B4`는 픽셀 단위다.

### 이동 상태와 표시 상태 분리

원본 카메라 블록은 바람 갱신 `0x424E50`과 난수 호출까지 포함한다. 가장자리 조건을 단순히 없애거나 바람 갱신을 매 프레임 실행하면 항해 계산이 달라진다. 따라서 별도의 런타임 데이터에 **원본 가장자리 카메라**를 보관한다. 이동 함수의 `0x47D0E5`에서 이 원점을 복원하고 원래 이동·충돌·시야·바람 코드를 그대로 실행한 뒤, `0x47D43D`에서 확정된 주인공 위치를 기준으로 표시용 원점을 계산한다. 최초 지도 표시 때도 같은 계산을 수행한다.

표시용 픽셀 원점은 X=`(주인공 X - 화면 폭/2) mod 40000`, Y=`clamp(주인공 Y - 화면 높이/2, 0, 20000 - 화면 높이)`이다. 원점을 16으로 나눈 몫을 게임의 타일 원점에 저장하고 나머지 `rx/ry`를 그리기 보정에 사용한다. 지도 북단·남단에서는 배보다 지도 경계를 우선해 빈 화면이 생기지 않도록 한다. 외부에서 위치·원점이 바뀌면 로드·순간이동으로 판단하여 숨겨진 카메라를 다시 초기화한다.

`0x489360`을 통해 여섯 애니메이션의 화면 좌표를 새 타일 원점에 맞춘다. X 원점 차이는 세계 연결을 고려한 가장 짧은 부호 있는 차이로 계산한다. `0x426790`의 NPC 표시 목록 재구성은 같은 인물 ID의 이전 상태·애니메이션 프레임을 복구하여 이동 때마다 프레임이 0으로 돌아가지 않도록 한다. 날짜·발견·조우 루틴은 추가 호출하지 않는다.

v2에서는 월드 루프의 이동 호출 `0x48EF55 → 0x48D0A0`을 하나의 처리 단위로 묶는다. 고속 항해 수정이 한 번의 이동을 여러 조각으로 나누더라도 원본 카메라 전환은 처음에 한 번만 수행하고, 표시용 중앙 정렬과 NPC 목록 재구성은 다음 화면 출력까지 미룬다. 각 조각의 원래 충돌·시야·바람 처리는 그대로 실행한다.

### 이동 주기와 화면 주기 분리 (v2)

원래 월드 타이머 `0x48B120`은 `GetTickCount`와 `0x5697D4`의 기한을 비교하고, `0x48B145`의 100ms 단위로 다음 기한을 계산하여 이벤트 2를 발생시킨다. 따라서 배를 중앙에 고정하기만 하면 약 10Hz의 이동이 배경 전체의 계단식 움직임으로 드러난다. 공용 idle 콜백에도 50ms 제한이 있으므로 이 타이머 호출만 늘려서는 충분하지 않다.

`world_map_follow_smooth.py`는 물리 타이머의 상수·기한을 변경하지 않는다. 월드 루프의 `0x48EC84 → 0x459CC0` 대기 중에만 공용 입력 폴링 `0x4B8D27 → 0x4B8D3F`을 확장하여 약 16ms 간격으로 표시 전용 이벤트 4를 전달한다. `GetTickCount`의 15/16ms 단위를 한 번씩 건너뛰지 않도록 문턱은 15ms로 두며, 시스템 타이머 해상도는 변경하지 않는다. 실제 입력 이벤트가 우선이며, 이 대기 밖에서는 원래 폴링으로 바로 넘긴다. 이벤트 4는 대기 래퍼 내부에서 소비하고 `0x48EC04`의 그래픽 원점 설정·지도 출력·화면 전송으로만 되돌아간다. 날짜·조우·이동을 실행하는 외부 루프나 이벤트 2 경로로 보내지 않는다.

v2~v5의 `0x48EC3B` 그리기 래퍼는 표시 시작·끝 위치를 매번 100ms 구간에서 선형 보간했다. v6의 구간 연결 변경은 아래에 별도로 설명한다. 그림을 그리는 동안만 주인공 좌표를 표시용 위치로 바꾸고, 반환 전에 원래 물리 좌표를 복구한다. 따라서 표시 지연은 생기지만 실제 이동 속도·이동량·진행 시간은 바뀌지 않는다. 세계 좌우 연결은 가장 짧은 방향으로 보간한다. 메뉴·정지·특수 연출·로드/위치 변경·해상도 변경은 보간 구간을 취소하며, 추가 화면에서 이벤트 애니메이션 카운터가 더 진행하지 않게 보존한다.

비·눈 효과의 `0x49ABB0` 하위 렌더러는 효과 프레임뿐 아니라 공용 난수도 진행시킨다. v2~v4에서는 효과 관리자 `0x5B6840/44`가 모두 `-2`(완전히 비활성)일 때만 중간 화면을 허용했다. `-1`은 종료 정리 중이므로 비활성으로 취급하지 않았다. 이 보호 조건 때문에 비·눈이 오면 카메라도 원래 약 100ms 갱신으로 돌아가 끊겨 보였다. v5에서는 아래의 날씨 그림 재사용 방식으로 분리한다. 다른 특수 연출은 계속 원래 주기를 유지한다.

### 픽셀 스크롤과 입력

`0x48A1E0`의 실제 지도 분기 `0x48A2A9`에서 화면 원점과 소프트웨어 출력 원점을 `-rx/-ry`만큼 이동하고, 고정 정보 표시 직전과 함수 반환 시 복원한다. 기존 도시 이름 훅 `0x48AB38`과 페이로드는 변경하지 않는다. 타일·함선·애니메이션의 DirectDraw 경로는 같은 잔여 픽셀 보정을 적용하며 목적 사각형을 지도 영역으로 자른다. 소스 사각형도 같은 양만큼 잘라 크기를 유지한다. 재시도에 쓰는 원본 사각형은 수정하지 않는다.

타일 반복 수는 `ceil((화면 픽셀 크기 + 잔여 픽셀)/16)`으로 계산한다. 타일 수가 정수가 아닌 해상도에서도 오른쪽·아래쪽을 채우되, 기존 캐시·마스크의 할당 크기나 행 간격은 늘리지 않는다. 추가 가장자리 셀은 두 배열을 읽거나 쓰지 않고 그리기만 수행한다. 지도 원점·잔여 픽셀·화면 크기·출력 대상이 바뀌면 다시 출력하고, 고정된 화면에서는 원래 타일 캐시를 재사용한다. 선박과 도시 이름이 표시된 부분은 기존 캐시 무효화를 통해 다시 그려 잔상을 지운다.

v2의 DirectDraw 경로는 타일별 `Blt` 대신 지도 표면을 한 번 `Lock`하여 배경 타일들을 복사하고, NPC·주인공·효과를 그리기 전에 `Unlock`한다. 복사 원본은 게임이 DirectDraw 타일 아틀라스를 만들 때 사용한 `view+0xB0`의 같은 8비트 픽셀이다. 표면 크기·픽셀 형식·pitch·복사 범위를 검증하고, 지원하지 않는 표면이나 잠금 실패에서는 원래 `Blt` 경로를 사용한다. 잠금이 유지된 채로 함선이나 HUD를 그리지 않도록 종료 경로를 분리한다.

진행 방향 클릭 `0x48ECEF`와 인접 타일 선택 `0x48BAA6`은 마우스 좌표에 잔여 픽셀을 더한 뒤 기존 계산으로 넘긴다. 인접 타일 선택의 번호와 선택 사각형도 같은 양만큼 이동한다. 다른 UI의 좌표·문자 출력 함수 자체는 변경하지 않는다.

### 일반 구름의 픽셀 보정 누락 수정 (v3)

일반 구름 6개는 비·눈 효과와 달리 `0x4893A0 → 0x489110`의 별도 DirectDraw 경로를 사용한다. 화면 좌표는 `0x5B6890`부터 8바이트 POINT 6개이며, `0x489360`이 타일 원점 차이 × 16만큼만 보정한다. v1/v2는 `0x4891F3`의 구름 Blt 호출에 잔여 픽셀 `rx/ry`를 적용하지 않아, 배가 0/1/7/15/16픽셀 이동할 때 구름 X가 200/200/200/200/184로 계단식 변화했다. 정상 출력은 200/199/193/185/184이다. 풍속·난수 변경이나 원점 보정의 누적 오차가 아니라, 출력 단계의 픽셀 보정 누락으로 재현했다.

v3는 `0x4891C0`에서 원래 클리핑 함수 `0x4892F0`를 호출하기 전에 전체 원본·목적 사각형을 보관한다. 구름 Blt는 그 사각형의 복사본에 공통 잔여 픽셀 보정과 클리핑을 적용한다. 먼저 잘린 사각형을 이동하면 오른쪽·아래쪽 일부가 사라지므로, 반드시 자르기 전의 사각형을 사용한다. 원래 사각형은 타일 캐시 무효화와 표면 재시도에 그대로 남기며, 구름 POINT·풍속 누적값·프레임은 수정하지 않는다. `0x489285`의 캐시 쓰기는 원래 열·행 수 안에서만 허용하여 16의 배수가 아닌 화면 크기의 가장자리 셀이 할당 범위를 벗어나지 않도록 한다. 캐시가 없는 추가 가장자리 타일은 기존 중앙 추적 렌더러가 매번 다시 그린다.

### 해류 무늬와 이동 구간의 연속성 수정 (v4)

물 타일의 해류 무늬 선택은 `0x48A4F7..0x48A551`에서 방향 벡터·해류 세기·원래 애니메이션 시계 `0x569554`를 이용한다. 기존 곱셈 두 곳은 화면 내부 열(`[esp+0x1C]`)·행(`[esp+0x18]`)을 사용한다. 따라서 시간과 해류를 고정해도 같은 월드 타일 X=108이 카메라 원점 한 칸 이동으로 타일 128에서 1408로 바뀌었다. 그리기 좌표 자체가 아니라 무늬 선택 기준이 화면에 붙어 있던 문제다.

중앙 추적 활성 시에만 `0x48A518`의 X 곱셈은 실제 월드 X(`[esp+0x58]`), `0x48A525`의 Y 곱셈은 실제 월드 Y(`[esp+0x54]`)를 사용한다. X는 원래 지도 조회가 이미 2,500칸 범위로 감싼 좌표다. 같은 월드 타일은 카메라의 잔여 픽셀·타일 원점·세계 좌우 경계 통과와 무관하게 같은 시간에 같은 무늬를 유지한다. 해류 방향·세기·시간 진행은 바꾸지 않는다.

기존 보간은 이동 처리가 끝날 때마다 이전 물리 위치를 시작점으로 재설정했다. 원본 타이머의 기한은 100ms 격자를 유지하지만 실제 콜백 간격은 다를 수 있다. 네이티브 타이머를 실행한 재현에서 1051ms에 시작한 +96픽셀 이동은 1096ms에 +43픽셀을 표시하다가, 1101ms의 다음 처리 직후 +96픽셀로 뛰었다. 이동 처리 자체가 늦어지는 경우에도 같은 종류의 불연속이 발생했다.

v4는 다음 이동 전의 표시 구간이 유효한지 확인하고, 이동 처리 완료 시각에서 그 구간의 표시 위치를 다시 계산하여 다음 보간의 시작점으로 이어 붙인다. 물리 좌표가 변하지 않은 틱은 진행 중인 구간을 새로 시작하지 않는다. 타이머의 기한·원본 이동 함수·난수 호출은 그대로 두고 표시 구간만 변경한다. v4까지는 메뉴·로드·날씨 등 기존 보간 중단 조건도 유지했다.

### 비·눈이 올 때의 카메라 보간 (v5)

강수 처리는 일반 구름과 별개다. 지도 렌더러는 `0x48AA6E`에서 비(효과 0), `0x48AAC2`에서 눈(효과 1)을 `0x49ABB0`으로 전달한다. 비는 `0x61E018`의 입자 75개, 눈은 `0x61DBF8`의 입자 50개를 사용한다. 정상 출력 중 입자 좌표·눈의 위상·종료 카운터가 변경되고, 화면 밖 입자의 재배치에는 공용 난수가 사용된다. 최초 출력과 종료에는 DirectDraw 표면 생성·해제도 포함된다. 추가 화면마다 이 함수를 다시 실행하거나 실행 후 메모리만 되돌리는 방식은 사용하지 않는다.

`world_map_follow_weather.py`는 정상 화면의 날씨 호출을 그대로 실행하면서 실제 그려진 입자의 X/Y, 원본 표면, 그림 번호, 크기를 기록한다. 중간 화면에서는 직전 기록으로 클리핑(`0x49A620`), 그림 출력(`0x49A700`), 타일 캐시 무효화(`0x49A050`)만 실행한다. 효과 진행 함수·난수·초기화·자원 해제는 호출하지 않는다. 날씨 그림을 준비하지 못했거나 기록의 화면·표면·상태가 현재와 맞지 않으면 추가 화면을 기다리고 정상 화면이 새 기록을 만들도록 한다.

실제 지도 렌더러는 특수 효과 번호가 `-1`이어도 `0x48AB1E`에서 공용 효과 함수를 호출한다. 그 내부의 `0x49A010`은 번호 검사 전에 공용 효과 카운터 `0x61D780`을 갱신하므로, 날씨 호출 두 곳만 분리해서는 충분하지 않다. 표시 전용 화면에서는 `view+0x10C`와 함께 이 카운터도 보존·복구하여 다음 정상 날씨 프레임의 입자 표시 수와 난수 호출 순서가 달라지지 않도록 한다.

비·눈 입자는 월드 좌표가 아니라 화면 좌표다. 날씨 출력에만 화면 고정 표시를 적용하여 카메라의 잔여 픽셀 값이 15→0으로 돌아갈 때 강수 그림이 튀지 않도록 한다. 타일 캐시 무효화 좌표에는 반대로 `rx/ry`를 더해 실제로 덮은 지도 셀을 지운다. 일반 구름·함선·발견물 특수 효과에는 이 예외를 적용하지 않는다. 메뉴 진입/복귀, 종료, 화면 변경이나 날씨 표면 교체 시 오래된 기록을 재사용하지 않는다.

### 소수 위치와 표시 기한의 연속성 수정 (v6)

v4/v5는 이전 구간의 표시 위치를 이어 받지만, 그 위치를 정수 픽셀로 잘라 저장하고 새 구간을 매번 100ms로 시작했다. 원본 타이머 `0x48B120`을 실행하고 `GetTickCount`를 15.625ms 단위로 재현하면 갱신 시각은 1046, 1140, 1250, 1343, 1437, 1546ms처럼 흔들린다. 1픽셀씩 이동하는 테스트에서 v5의 화면 픽셀 변경 간격은 46~157ms가 되어, 일정한 물리 이동에도 빨라졌다 멈추는 표시 패턴이 생겼다. 이는 날씨와 무관하게 기계어 실행으로 재현한 보간 결함이다. 실행 중인 게임을 읽기 전용으로 측정한 구간에는 실제 이동이 잡히지 않았으므로, 사용자가 보고한 화면의 모든 튐을 이 결함 하나로 확정하지는 않는다.

v6는 표시 시작 위치와 이동량을 Q8 고정소수점(1/256픽셀)으로 유지한다. 새 구간 연결과 화면 출력은 같은 샘플 함수를 사용하며, 실제 그리기에 넘길 때만 절대 좌표를 가장 가까운 정수 픽셀로 반올림한다. X 좌표는 소수 위치와 출력 좌표 모두 세계 너비로 감싸고, 이동량은 가장 짧은 방향을 사용한다.

진행 중인 구간에 다음 이동이 들어오면 표시 끝 기한은 `max(이전 표시 끝 기한, 이동 처리 완료 시각) + 100ms`로 이어 간다. 새 구간 길이는 100~200ms로 제한하여 빠른 연속 처리로 지연이 무한히 쌓이지 않게 한다. 이동이 늦어 기존 기한을 넘긴 경우에는 한 번 기준을 다시 잡는다. 물리 좌표가 바뀌지 않은 틱은 기존 구간과 기한을 유지한다. 원래 물리 타이머·이동·날짜·조우·입력 우선순위는 바꾸지 않는다. 최장 이동량 20,000픽셀 × 256 × 200ms도 부호 있는 32비트 곱셈 범위 안에 있다.

이 변경은 보간 단계의 정밀도 손실과 구간 시간 재설정을 수정하는 것이다. 실제 렌더링·드라이버가 오래 멈춰 중간 프레임을 표시하지 못하는 경우까지 없애는 것은 아니며, 실제 플레이 화면은 별도 확인이 필요하다.

### 저장·검증

`.patch +0x51A00`부터 `0x8000`바이트를 별도 예약하고, 슬롯 `+0x6000` 이후는 EXE 로드 시 0으로 초기화되는 쓰기 가능한 실행 상태로 사용한다. 세이브 파일에 새 필드를 추가하지 않는다. `CDSWMC1` 식별자, 모든 훅 원본·변경 명령, 페이로드 전체를 검증한다. 해제 시 원래 명령을 복원하고 슬롯을 비운다. 통합 저장에서는 좌표 형식 재작성 전에 추적 훅을 해제하고 다른 패치 적용 후 마지막에 다시 적용한다.

슬롯 내부 버전 2부터 `+0x4000..+0x5800`을 화면 보간 코드에 사용하며, v5부터 날씨 재표시 코드는 `+0x2800..+0x4000`을 사용한다. `world_map_follow_v1.py`부터 `world_map_follow_v5.py`까지는 실제 적용된 이전 생성기를 동결한 호환성 전용 모듈이다. 이전 페이로드·모든 훅을 완전히 확인한 뒤 원본을 복구하고 소수 위치·표시 기한 연결까지 포함한 v6를 설치하므로, 이미 체크된 상태로 다시 저장해도 최신 코드로 갱신된다. 알려지지 않은 버전이나 손상된 훅은 추측해서 덮어쓰지 않는다. 이 번호는 앱 배포 버전과 별개다.

기계어 실행 테스트로 원본과 동일한 이동 결과·바람/RNG 호출·시야 갱신, 픽셀 중앙 정렬, 좌우 세계 연결, 남북 경계, 충돌·로드, NPC 상태 보존, 입력과 선택 표시 보정을 확인한다. 보간은 양방향 저속·고속 이동, 원본 타이머의 15/16ms 단위, 이른/늦은 갱신, 구간 지연 제한, 정지·방향 전환·시계 순환을 검사한다. 실제 비 75개·눈 50개의 정상 갱신과 중간 화면 재표시, 초기화·종료·화면 경계, 원본 타이머와 전체 지도 렌더러에서의 입자·공용 효과 카운터·난수 보존도 검사한다. 고속 항해 및 도시 이름 패치와의 적용·해제·재저장도 검사한다. 실제 DirectDraw 드라이버와 인게임 화면의 외관·성능은 별도 플레이 확인이 필요하다.
