# CDS_95.EXE 분석 기록

패처가 실제로 수정하거나 확인하는 실행 코드의 근거를 간단히 기록한다. 주소는 한국어판 `CDS_95.EXE`의 가상 주소(VA) 기준이다.

## 인물 능력치와 생명력 상한

| 항목 | 원본 위치 | 원본 상한 | 패처 허용 범위 | 비고 |
|---|---:|---:|---:|---|
| 체력·지력·무력·매력·운·신앙심 | `0x432C50` | 100 | 0~255 | 여섯 능력치가 하나의 공통 판정 함수를 사용한다. |
| 생명력 | `0x432C87` | 2000 | 0~9999 | 상한 즉시값 하나를 사용한다. |

능력치 함수는 내부값에 1을 더해 범위 판정을 한 뒤 다시 1을 빼서 저장한다. 따라서 패처는 상한을 255로 바꿀 때 8비트 부호 있는 즉시값을 쓰지 않고 32비트 값으로 기록한다. `255`를 잘못 8비트 값으로 기록하면 게임에서는 `-1`로 해석될 수 있기 때문이다.

생명력 HUD는 `0x47DFC9`에서 형식 문자열 `HP:%4d`를 사용하며, 표시 칸 폭은 `0x569210` 테이블의 7글자다. 따라서 0~9999는 정상 표시 범위이고, 10000 이상은 표시 칸을 넘길 수 있어 허용하지 않는다.

## 소지금·저금 상한

게임 내부에는 소지금과 저금의 상한 판정 경로가 별도로 있다. 패처 화면에서는 두 값을 분리해 관리하지 않고 `소지금·저금 공통 상한` 하나만 제공하며, 적용 시 두 경로에 같은 값을 기록한다. 허용 범위는 1~99,999,999 두캇이다.

## 주인공 명성·악명 상한

주인공 명성과 악명은 `0x4800E0`의 공통 상한 함수에서 처리된다. 패처 화면은 `명성·악명 공통 상한` 하나만 제공하며, 적용 시 두 경로에 같은 값을 기록한다. 이전에 오인하기 쉬웠던 `0x474188`은 함대 식량 상한 경로이며, 명성 상한 위치가 아니다.

## 선박 구입 목록의 빈 슬롯

`0x44B616`의 선박 구입 선택 루프는 현재 도시에서 구매 가능한 선종을 임시 배열(`EBP-0x34`)에 채운 뒤, 후보 수를 `EBP-0x10`에 보관한다. 선택 창이 반환한 행 번호는 `0x44B626`에서 `EDI`에 저장되며, 원본은 취소값 `-1`만 검사한 뒤 `0x44B65D`에서 `EDI`를 배열 인덱스로 사용한다.

도크로 판매 가능한 선종이 줄어 목록에 빈 행이 남은 상태에서 그 행을 누르면 `EDI >= 후보 수`가 될 수 있다. 이 값은 배열 범위를 벗어나므로 잘못된 선종 포인터를 따라가 게임이 종료된다. 패처의 버그 수정은 `0x44B628`의 취소 검사만 코드 케이브로 우회해 다음 순서로 검사한다.

1. `EDI == -1`이면 원래 취소 경로(`0x44B781`)를 그대로 사용한다.
2. 음수이거나 `EDI >= [EBP-0x10]`이면 선택 루프(`0x44B616`)로 되돌린다.
3. 유효한 인덱스만 원래 배열 참조 직전(`0x44B631`)으로 보낸다.

따라서 정상 선택·취소 흐름은 유지되고, 빈 행 선택만 다시 선박 목록으로 돌아간다.

## 주점 힌트 버그 수정

주점 힌트 마스터는 `0x525078`에서 시작하는 24바이트 레코드 191개다. 레코드 첫 4바이트는 대상 코드이고, 이어지는 4개의 부호 있는 32비트 값은 힌트를 들을 수 있는 도시 ID다.

- 힌트 88은 크노소스를 설명하지만 대상 코드가 `302`로 저장되어 있어, 발견물 코드 `112`로 보정한다.
- 힌트 152의 카카오 대사는 첫 제공 도시가 메리다(`206`)로 저장되어 있으나, 미틀라(`204`)에서 출력되어야 하므로 해당 도시 ID만 보정한다.

두 수정은 하나의 `주점 힌트 버그 수정` 항목으로 적용·복원된다. 이전 패처에서 크노소스 수정만 적용한 EXE는 적용 상태로 인식하며, 다음 저장 시 카카오 제공 도시도 함께 보정한다.
